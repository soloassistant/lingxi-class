# 学情周报定时推送 · 部署与配置说明

对标学而思「学情周报」，补齐"没人催着学"的留存短板。整条链路：

```
用户点击「订阅学情周报」
  → wx.requestSubscribeMessage 拿到一次性订阅授权
  → subscribeWeekly 云函数落一条 pending 订阅记录
  → 每周一 09:00 sendWeeklyReport 定时触发
      → 汇总本周学习数据（新学知识点 / 学习天数 / 正确率 / 待复习错题）
      → 生成周报摘要，写入 weekly_reports
      → subscribeMessage.send 推送，消费一条订阅记录
  → 用户点消息 → 落地 pages/report/report 查看完整周报
```

---

## 一、涉及的三块代码

| 类型 | 路径 | 作用 |
|---|---|---|
| 云函数 | `cloudfunctions/subscribeWeekly` | 记录订阅授权（一次授权 = 一条可发送额度） |
| 云函数 | `cloudfunctions/sendWeeklyReport` | 定时生成 + 推送周报（含定时触发器） |
| 云函数 | `cloudfunctions/getWeeklyReport` | 报告页读取最近一期周报 + 订阅状态 |
| 页面 | `miniprogram/pages/report/report.*` | 周报卡片 + 订阅按钮（推送落地页） |
| 页面 | `miniprogram/pages/profile/profile.*` | 「学习报告」「订阅学情周报」入口 |

## 二、新增数据集合

| 集合 | 说明 | 建议索引 |
|---|---|---|
| `subscriptions` | 订阅授权记录：`openid / templateId / status(pending\|used\|failed) / attempt / lastError / createTime / usedTime` | `openid + status`、`templateId + status` |
| `weekly_reports` | 周报内容：`openid / weekKey / weekStart / learnedThisWeek / studyDays / accuracy / pendingWrongs / weakTop / suggestion / pushed` | `openid + weekKey`、`openid + weekStart` |
| `learner_prefs` | 用户偏好：`openid / weeklyReport` | — |
| `ai_usage_global` | AI 全站日用量（频控用，非周报链路）：`date / count` | `date` |
| `ai_calls` | AI 调用明细（频控用）：`openid / ts` | `openid + ts`（建议配 TTL 清理） |

> 三个集合若不存在，云函数首次写入时会自动尝试创建；仍建议在控制台手动建好并加索引，避免首次调用变慢。

## 三、必须手动配置的两件事

### 1. 申请订阅消息模板（不配则推不出去）

1. 打开微信公众平台 → 小程序 → **功能 → 订阅消息**
2. 从公共模板库选一个"学习报告/每周学习情况"类模板，关键词建议：
   - `thing1` 报告名称
   - `number2` 新学知识点数
   - `number3` 学习天数
   - `number4` 待复习错题数
   - `thing5` 老师建议
3. 拿到 **模板 ID**，替换两处占位符：
   - `cloudfunctions/subscribeWeekly/index.js` → `TEMPLATE_ID`
   - `miniprogram/pages/report/report.js` → `onSubscribeWeekly` 内的 `TEMPLATE_ID`
   - `miniprogram/pages/profile/profile.js` → `onSubscribeWeekly` 内的 `TEMPLATE_ID`
   - （`sendWeeklyReport` 支持用环境变量 `WEEKLY_TEMPLATE_ID` 覆盖）

> 模板字段名（`thing1`/`number2`…）以你实际申请的模板为准，需与 `sendWeeklyReport` 里 `data` 的键一一对应，否则会报 47003。

### 2. 上传云函数并确认触发器

`sendWeeklyReport/config.json` 已写死定时触发器：

```json
{ "triggers": [{ "name": "weeklyReportTimer", "type": "timer", "config": "0 0 9 * * MON *" }] }
```

含义：**每周一 09:00**（北京时间）执行一次。

上传时在微信开发者工具里对 `sendWeeklyReport` 右键 →「上传并部署：云端安装依赖」，**勾选"上传触发器"**。上传后到云开发控制台 → 云函数 → `sendWeeklyReport` → 触发器，确认 `weeklyReportTimer` 已存在。

同时确认该云函数的权限里已开通 `subscribeMessage.send`（`config.json` 的 `permissions.openapi` 已声明，上传后会被自动写入）。

## 四、验证方式

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 小程序内点「订阅学情周报」→ 允许 | 提示"订阅成功"，`subscriptions` 多一条 `status: pending` |
| 2 | 云开发控制台 → `sendWeeklyReport` → 云端测试，传入 `{}` | 返回 `{ code:0, sent:1 }`，`weekly_reports` 多一条且 `pushed: true` |
| 3 | 微信「服务通知」 | 收到学情周报消息，点开跳 `pages/report/report` |
| 4 | 再手动触发一次 | 返回 `skipped:1`（同一周幂等，不重复推） |
| 5 | 测试单人：传入 `{"openid":"xxx"}` | 只推该用户，便于调试 |

## 五、几个容易踩的坑

1. **一次性订阅语义**：`wx.requestSubscribeMessage` 默认是"授权一次只能推一条"。所以 `subscribeWeekly` 每授权一次写一条 pending 记录，`sendWeeklyReport` 每推成功消费一条。想让用户订多期，要么让用户多点几次，要么申请**长期订阅模板**（目前仅政务/医疗等类目可申请，教育类通常拿不到）。
2. **必须由用户点击触发**：订阅授权接口只能在用户点击事件里调用，不能自动弹。所以入口放在报告页按钮和「我的」菜单里。
3. **幂等保护**：`weekly_reports` 以 `openid + weekKey` 唯一（upsert），同一自然周只推一次；`pushed: true` 是"已推送"的唯一判据，推送失败不算已推，保留记录供报告页回看。
4. **失败自动重试**：`sendMessage` 失败时若属于可重试错误（网络抖动），订阅记录保持 `pending` 不消耗额度，并累加 `attempt`；连续失败 3 次、或属于确定性失败（模板未配置 / errCode 43101 用户拒收 / 47003 参数错误）才置 `failed` 放弃。这样既不会因一次抖动漏推，也不会无限重试坏数据。
5. **超时保护**：单次批处理上限 100 人（`BATCH`），用户量大时需要把定时任务改成多次分批，或按 `createTime` 分页续跑。
6. **只在正式版可用**：`miniprogramState` 默认 `formal`。体验版/开发版想收消息，把云函数环境变量 `MP_STATE` 设为 `trial` / `developer`。
