# API Key 安全接入指南

> ⚠️ **本文档不含任何真实密钥。** 密钥只存在于云端环境变量，永远不写进代码、文档、聊天记录或 git 仓库。

---

## 一、最重要的一件事：泄露的 key 必须立即作废

任何**曾经以明文出现在聊天、代码、截图、文档里**的 key，都应当视为已泄露。

**处理原则：不是"藏起来"，而是"换掉"。**

| 动作 | 说明 |
|---|---|
| 1. 作废 | 去服务商后台（如 DeepSeek / OpenAI 控制台）**删除或禁用**已泄露的那个 key |
| 2. 重建 | 生成一个新 key，**不要再发给任何人、不要贴在对话里** |
| 3. 检查账单 | 查看泄露期间是否有异常调用/扣费，确认没有被盗刷 |
| 4. 复盘入口 | 想清楚它当初是怎么流出的，堵住那个入口 |

> 为什么不能"打码后继续用"：对话记录、日志、剪贴板、grep 历史都可能留存明文；一旦进入 git 提交历史，`git log -p` 永久可查，删文件也删不掉历史。

## 二、正确的存放位置：云函数环境变量

本项目的 AI 调用链是：

```
前端页面 → 云函数（aiTeach / aiExplain / searchProxy ...） → aiProxy → 上游大模型
                                                              ↑
                                                    从这里读环境变量
```

**密钥只在 `aiProxy` 一个地方被读取**（`cloudfunctions/aiProxy/index.js`）：

```js
const keys = [process.env.AI_KEY_PRIMARY, process.env.AI_KEY_SECONDARY].filter(Boolean);
```

前端拿不到、代码仓库里没有真实值。这是唯一正确的放置方式。

### 配置步骤

微信开发者工具 → 云开发控制台 → 云函数 → **`aiProxy`** → 配置 → **环境变量**，新增：

| 变量名 | 必填 | 说明 | 示例值 |
|---|---|---|---|
| `AI_KEY_PRIMARY` | ✅ | 主力 key（在控制台粘贴，不写进文件） | `<你的新 key>` |
| `AI_BASE_URL` | ✅ | 上游 API 地址 | `https://api.deepseek.com/v1` |
| `AI_MODEL_PRIMARY` | ✅ | 主模型 | `deepseek-chat` |
| `AI_KEY_SECONDARY` | 建议 | 备用 key，主 key 失败时自动切换 | `<备用 key>` |
| `AI_MODEL_SECONDARY` | 建议 | 备用模型 | `deepseek-chat` |
| `AI_DAILY_QUOTA` | 可选 | 单用户每日调用上限（默认 20） | `20` |
| `AI_GLOBAL_QUOTA` | 可选 | **全站**每日调用上限（默认 2000，预算封顶） | `2000` |
| `AI_RATE_MAX` | 可选 | 单用户每分钟调用上限（默认 10） | `10` |
| `AI_SECURITY_CHECK` | 可选 | 设为 `off` 关闭内容安全检测（默认开启） | 留空 |

> 环境变量只在云端运行环境生效，前端反编译、代码仓库、CI 日志里都拿不到。

## 三、四层防滥用机制（已实现在 aiProxy）

即使有人拿到你的小程序、批量注册账号来刷 AI，也有止损：

| 层级 | 机制 | 拦截什么 |
|---|---|---|
| 1 | **登录上下文校验**：无 `OPENID` 直接 401 | 非微信环境的裸调用（如有人直接构造 HTTP 请求打云函数） |
| 2 | **单用户频控**：`AI_RATE_MAX` 次/分钟 | 脚本高频刷（正常用户打字不可能每分钟 10 次提问） |
| 3 | **单用户日配额**：`AI_DAILY_QUOTA` 次/天 | 单个账号被滥用 |
| 4 | **全站日上限**：`AI_GLOBAL_QUOTA` 次/天 | 批量注册账号的刷量攻击，把总消耗封顶在预算内 |
| 5 | **连续失败冷却**：故障时冷却 60 秒 | 上游故障时的无效重试放大 |

**另外两条隐私保护**：
- **错误信息泛化**：上游报错只写服务端日志（`console.error`），返回给前端的永远只有"AI 服务暂时不可用"，不泄露上游细节或 key 状态。
- **输入长度限制**：单次 prompt 上限 4000 字符，防止用超长输入刷 token。

## 四、新增数据集合

| 集合 | 用途 | 建议索引 |
|---|---|---|
| `ai_quota` | 单用户每日用量：`openid / date / count` | `openid + date` |
| `ai_usage_global` | 全站每日用量：`date / count` | `date` |
| `ai_calls` | 调用明细（分钟级频控用）：`openid / ts` | `openid + ts` |

> `ai_calls` 会持续增长，建议配 TTL 索引自动清理（如保留 2 天），或在定时任务里清理过期记录。

## 五、日常安全检查清单

- [ ] 代码仓库里搜不到真实 key：`grep -rn "sk-" .`（应无结果）
- [ ] `.gitignore` 已排除 `.env`、`config.local.js` 等本地配置文件
- [ ] 密钥只配在 `aiProxy` 云函数环境变量里，其他云函数不直接持有
- [ ] 上游后台已设置**消费限额/告警**（这是最后一道保险，强烈建议开启）
- [ ] 定期轮换 key（建议 3-6 个月，或怀疑泄露时立即轮换）
- [ ] 团队成员若需权限，在云开发控制台给"云函数配置"权限，而非共享 key 明文

---

## 六、如果发现 key 被盗用

1. **立刻在服务商后台禁用该 key**（停止出血）
2. 检查账单/用量曲线，确认损失范围
3. 生成新 key，更新到 `aiProxy` 环境变量
4. 检查上游后台的调用来源 IP、时间分布，判断泄露渠道
5. 收紧 `AI_GLOBAL_QUOTA` / `AI_RATE_MAX`，观察一段时间再放开
