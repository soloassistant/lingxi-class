# 学习事件与指标口径（R11）

本文说明"学习数据从哪来、指标怎么算"。**部署前必读**。

## 1. 为什么需要一张独立的作答事件表

仪表盘原来的"答题正确率"是这么算的：

```
wrong_books.where({ status: 'reviewing' })  →  rightCount / (rightCount + wrongCount)
```

这份样本有三重偏差，叠在一起结论必然失真：

| 偏差 | 后果 |
| --- | --- |
| 首次答对不进 `wrong_books`（只走 `progress`） | 分子天然缺一块，正确率被系统性拉低 |
| 间隔重复"毕业"（`status: 'resolved'`）的题被排除 | 学得越好，分子掉得越多 |
| `saveWrong` / `updateWrong` 会把 `rightCount` 归零、覆盖 `updateTime` | 历史被改写，无法反推 |

实测表现：正常保存一个**答对**的知识点后，仪表盘显示 `learned=1, accuracy=0` ——
自相矛盾的反馈，而且这个数会出现在个人中心、学情周报和给家长看的页面上。

同类问题还有"活跃天数"：它读 `checkins` 集合，而**全仓没有任何写入路径**，
所以 `activeDays` 恒为 0、热力图恒为空白。

结论：**事实必须按"每次作答一条"留下来，指标一律从事件派生，
不能从"当前状态"反推历史。**

## 2. `answer_events` 集合

**部署前置条件：必须先创建 `answer_events` 集合。**
云函数端已做容错（首次写失败会 `createCollection` 后重试一次），
但仍建议在控制台预先建好，避免每条作答都多一次失败往返。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openid` | string | 归属用户（云函数从上下文取，客户端无法伪造） |
| `itemId` | string | 知识点 id |
| `courseId` | string | 所属课程。等级与掌握度按课程隔离，事件同样带范围 |
| `correct` | boolean | **权威事实**：这次作答判为对/错 |
| `graded` | boolean | 这次对错是**服务端判定**的（`true`），还是学生自评（`false`） |
| `source` | string | `quiz` / `lesson` / `review` / `self_mark` |
| `attemptId` | string | 幂等令牌（来自作答方，缺省空串） |
| `dayKey` | string | `YYYY-MM-DD`，**服务端按北京时间算好**，按天统计的唯一口径 |
| `ts` | number | 毫秒时间戳，用于窗口查询与排序 |
| `createTime` | Date | 服务端时间 |

只追加、不修改。写入方：`saveProgress`、`saveWrong`、`updateWrong`。

### 为什么 `dayKey` 在服务端算

云函数跑在 UTC。若用本机时区算"今天"，北京时间早上 8 点前的学习会记到前一天；
而学情周报本来就按 `+8` 算周一零点。两边口径不一致，同一份数据会出现两个日期。

### `graded` 为什么要单独标

学生自评"我已掌握"（课程页 `markLearned`）是**学习信号**，不是客观证据。
把它混进正确率，学生点几下按钮就能把正确率刷满。
所以：自评 `graded: false`，**不进正确率的分子也不进分母**，单独报 `selfMarks`。

## 3. 指标口径

### 正确率 `accuracy`

```
accuracy = round(答对的判定作答数 / 判定作答总数 × 100)     // 只看 graded = true
```

- **没有判定作答时返回 `null`，不是 0。** 0% 意味着"做过题且全错"，与"还没有数据"是两件事。
- 界面在 `null` 时显示 `—`，并把 `metricsNote` 一起显示出来（样本量 + 口径）。
- 同时返回 `accuracySample`（样本量）与 `accuracySince`（最早一条事件的日期），
  让读到这个数的人能判断它有没有依据、覆盖了哪段时间。
- `accuracyWindow` 为 `all-since-<日期>` 或 `empty`。**不做历史回填**：
  `progress` / `wrong_books` 的当前状态无法诚实还原每次作答，宁可显示"暂无"。

### 活跃天 / 连续天数 `activeDays` / `streak`

- 任何作答事件都算活跃（含自评），按北京时间自然日去重。
- `streak` 从今天往回连续计算；今天没有作答则从昨天起算。
- 窗口取近 400 天、单次最多 1000 条。若被截断，`streakIsLowerBound = true`，
  界面在数字后加 `+` —— 它是下界，不是精确值。

### 近 7 天 `weekAccuracy`

每天返回 `{ date, active, attempts, accuracy }`。当天 `attempts = 0` 时 `accuracy` 为 `null`。
不再用 `0` 冒充"当天有数据但全错"。

### 待复习错题 `wrongCount` / `pendingReview`

来自 `wrong_books` 当前状态，口径是"**当前待复习**数量"，这是它的正确用途
（不要再用它反推正确率）。超过 500 条时 `wrongListTruncated = true`，
薄弱点只在前 500 条里聚合。

## 4. 改动过的调用链

| 位置 | 改动 |
| --- | --- |
| `saveProgress` | 记一条 `correct: true` 事件；`graded` 由调用方给（自评 `false`） |
| `saveWrong` | 记一条 `correct: false` 事件（此前只在 `wrong_books` 里改当前状态） |
| `updateWrong` | 计入的作答才落事件：`duplicated`（重放）与 `tooEarly`（未到期）**不落**，否则连点就能刷高正确率 |
| `getDashboard` | 全部指标改由事件派生；删除 `checkins` 读取（无写入方的集合）；修日期键补零、修"昨天起算"游标 |
| `sendWeeklyReport` | `studyDays` / `accuracy` 改由事件派生；`accuracy` 可为 `null`；落库带 `attempts` |
| `exportUserData` | 不再导出口径不成立的 `checkinCount`；新增 `answerEventCount` / `gradedAttemptCount` / `selfMarkCount` |
| `deleteAccount` | 补 `answer_events`（新增）与 `analytics`（**原来漏了真正在写的集合**） |
| 小程序 `report` / `profile` | 正确率为 `null` 时显示 `—`；导出提示不再报"打卡 N 条" |

## 5. 已知遗留

- **不做历史回填。** 新口径上线前的老用户，在产生第一条事件前正确率显示 `—`。
- `streak` 超过 1000 条事件窗口时只是下界（界面已用 `+` 标注）。
- `checkins` 集合保留在 `deleteAccount` 的清理列表里，用于清除历史遗留数据，
  但已无任何读取方。确认线上也没有仓库外写入后可以整体删掉。
- "答题正确率"目前是全量历史口径。若产品需要按周/按月口径，
  在 `getDashboard` 里给 `ts` 加下界即可，无需改数据结构。
