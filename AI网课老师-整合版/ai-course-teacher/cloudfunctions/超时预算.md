# 云函数超时预算（架构约束）

> 起因：外部审查 **R15**。`aiProxy` 单次上游超时 25 秒、两个 key 顺序重试 → 最坏 50 秒，
> 而它的 `config.json` 总时长只有 30 秒。**主通道一超时，备份通道通常已经拿不到预算。**
> 更麻烦的是嵌套：`aiProxy` 被 8 个外层云函数调用，而**那些外层当时也是 30 秒** ——
> 外层必然先被平台强杀，且强杀发生在子调用 `await` 之中，本地没有任何兜底。

## 当前预算层级

```
外层调用方（8 个函数）           40s   必须 > aiProxy 的总时长，否则外层先死
  └─ aiProxy 函数本身            30s   ← cloudfunctions/aiProxy/config.json
       ├─ 全部上游重试的合计       26s   ← UPSTREAM_BUDGET_MS（给返回留 4 秒）
       └─ 单次上游尝试             15s   ← PER_ATTEMPT_MAX_MS
```

8 个外层函数（已从 30s 调至 40s）：
`aiExplain`、`aiCourseGen`、`aiInterject`、`aiVariation`、
`aiTeach`、`getRoadmap`、`homeworkReview`、`searchProxy`。

## 规则（改代码前先读这几条）

1. **外层严格大于内层。** 任何"调用另一个云函数"的函数，`timeout` 必须大于被调用者的 `timeout`，
   否则主通道一慢，外层先被强杀，内层的重试逻辑根本没机会跑。
2. **重试共享一个总预算，不是每个通道各给一份。** 用 `deadline` 消耗式推进：
   每次开新尝试前先算剩余，不够（`< MIN_ATTEMPT_MS`）就直接停，不再开一次注定被杀的请求。
3. **超时要覆盖响应体读取。** 拿到响应头 ≠ 拿到结果。
   `clearTimeout` 必须写在 `finally` 里，不能写在 `await fetch()` 之后 ——
   原来就写在那里，于是 `res.json()` 全程没有超时保护。
4. **常量只在一处定义。** 改动 `config.json` 的 `timeout` 时，
   必须同步改 `index.js` 里的 `FN_BUDGET_MS`；两处不一致时
   `_test/test-timeout-budget.js` 会红。

## 怎么自查

```bash
node _test/test-timeout-budget.js
```

它会核对：常量之间的大小关系、代码里是否真的用了 `Math.min(..., left)` 限制单次尝试、
`clearTimeout` 是否在 `finally` 里、以及**每个外层函数的 timeout 是否严格大于 aiProxy 的**。
