## 一句话讲清原理

小程序**不建自己的后端**。它作为网页版的第二个客户端，直接连网页版那套云服务 —— 所以是同账号、同数据，不是数据同步。

```
网页版 ─┐
        ├─→ WorkBuddy 云服务（唯一数据源）
小程序 ─┘
```

## 开工前需要准备的三件事

### 1. 一个小程序账号

- 到微信公众平台注册小程序，拿到 **AppID**
- 正式上线需要**备案**；只是想先看效果用「试用小程序」即可（有效期 14 天）

### 2. 在小程序后台配置服务器域名

这个**必须做，否则真机上一个请求都发不出去**（模拟器里可能看不出来）。

进「小程序后台 → 开发管理 → 开发设置 → 服务器域名」，在 **request 合法域名**里加上：

```
https://mp-api.app.workbuddy.host
```

同时建议加上上传/下载域名（用到图片或语音时需要）：

```
https://mp-api.app.workbuddy.host
```

> 为什么是这个域名：微信的白名单不接受通配符、条数有上限，所以平台给小程序用的是统一固定网关，而不是各应用自己的域名。
> 这个网关靠请求里的 `publishableKey` 找到正确的云环境 —— 所以**代码里那个 key 一定不能写错**。

### 3. 确认短信通道是开的

已实测确认开通（服务端会返回来自短信服务的真实错误，说明真的在调用短信服务）。
如果开发时收到「短信登录暂未开通」类错误，回来告诉我们，不要自己换登录方式。

## 你们不用管的事

- ❌ 不用申请任何 AI 的 API Key（模型调用走平台网关，用登录用户的配额）
- ❌ 不用申请短信服务（同上）
- ❌ 不用建数据库、不用写后端（数据在网页版那套云服务里）
- ❌ 不用做数据同步的定时任务（本来就是同一份数据）

## 三个最容易踩的坑（详细见规格书）

1. **登录时不要在「登录」按钮里重发验证码** —— 一次登录会发两条短信，而且用户永远验证不上（§4.2）
2. **同步必须先推后拉，删除要留墓碑** —— 顺序错了或没有墓碑，会出现「删掉的课自己回来」「本地改动被覆盖」（§6）
3. **费曼环节的「够不够格」要由服务端自己数** —— 不能采信客户端传来的统计值，否则能被绕过（§10.5）

## 有两件事需要你们知道背景

### ① 微信一键登录用不了（不是漏配）

实测：

```
POST /.cloud/auth/v1/login-wechat
{"error":"access_denied","error_description":"小程序未授权给 WorkBuddy"}
```

原因是平台把两类应用分开了：网页版属于 **Web 类型应用**，平台不为它提供微信登录；微信登录只对**小程序类型应用**开放 ——
但那是**另一个云环境**，数据与网页版不通。

所以「手机号 + 验证码」不是退而求其次，**它是唯一能实现「和网页版同账号」的方式**。

### ② 有一条通路依赖「小程序不发 Origin 头」

网页版的云服务会校验请求来源。实测：

| 请求特征 | 结果 |
|---|---|
| 带错误 `Origin` | **403 拒绝** |
| 不带 `Origin` | **放行** |

微信小程序的 `wx.request` 不带 `Origin`，所以现在能正常访问。
如果将来小程序请求开始返回 **403**，先怀疑这里，**不要**去改 `endpoint` 或改成手写请求。

## 已知问题（不用你们修，但要知道）

**`analytics_events` 表存在一个未登录可读可写的缺陷。**

未登录时 `auth.uid()` 返回字符串 `'anon'`（不是空），于是所有未登录访客共享同一个租户，能互相读到埋点。
实测未登录能读出 14 行他人数据、能写入（HTTP 201）。

**对你们的要求**：写埋点前先判断登录态，未登录直接 `return`。
数据库层面的修复由我们负责，**不要去改 RLS**。

## 验收怎么交

规格书第 12 章有完整清单（分登录 / 数据 / AI 与费曼 / 工程四组）。
请按组逐条自测并在交付说明里给出结果，特别是这几条 —— 它们是最容易表面通过、实际有问题的：

- 已注册手机号登录后，**能看到网页版建的课程**（这是「联动」成立的最直接证据）
- 在网页版删除的课程，小程序同步后**不复活**
- 客户端伪造费曼统计值 → **仍被判「没讲够」**
- 断网时的改动，恢复网络后能同步上去

遇到规格书 §13 列的五种情况请记录下来反馈，**不要自己绕过**。
